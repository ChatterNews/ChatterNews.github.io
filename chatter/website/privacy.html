Your work.
Your device.

Reviewed September 15, 2026. This page describes the GitHub-hosted Orbit website workflow.

Orbit is a static website with a local workspace. It has no student account server, cloud storage, analytics service, or automatic publishing connection.

What stays local

Student stories, recordings, images, projects, badges and crew notes are processed and stored locally in the browser on this device in the reviewed website workflow. Orbit does not upload that work to GitHub. Transcription and image checks run here too. Saving creates files in a folder you choose or starts a browser download. The website edition does not open a sharing service.

Visiting the site still makes a connection

Orbit opens directly. It downloads room tools as you use them and downloads a processing model when its feature needs it. Optional offline preparation stores the full toolkit. The browser also checks for app updates. Visiting the website and downloading its tools sends connection information to GitHub, including the device’s IP address and the public file requested.

GitHub’s hosting logs

GitHub’s Pages disclosure says visitor IP addresses are logged and stored for security purposes, including for visitors who are not signed in. Its General Privacy Statement governs its handling of hosting information. GitHub describes detecting and preventing abuse and security threats, data minimization, and administrative, technical and physical security controls.

Orbit’s application code does not use this connection information for advertising, contacting children, or building individual profiles. This statement about Orbit’s code is separate from GitHub’s handling of its logs.

How Orbit limits outgoing information

The website downloads public app tools, checks for updates and optionally caches tools for offline lessons. Its app gateway allows only listed public files, checks their size and checksum, and blocks other destinations, query strings and write requests. Allowed tool requests exclude caller-supplied headers, credentials and referrers. Story navigation stays in URL fragments, which are not included in HTTP requests. The reviewed app has no advertising, analytics or tracking-pixel integration. These safeguards limit Orbit’s requests; they do not control GitHub’s hosting logs.

Children’s privacy: what still needs verification

Where an operator relies on COPPA’s exception for persistent identifiers used to support internal operations, 16 CFR 312.4(d)(3) requires the notice to identify the specific operations and explain how other uses are prevented. Those restrictions cover contacting individuals, behavioral advertising, individual profiling and other purposes outside the permitted internal operations.

For this website, the operations described above are delivering public tools and updates, and GitHub’s stated security logging. Remaining gap: we have not verified a Pages-specific policy or agreement ensuring that visitor identifiers are used and disclosed only for permitted internal operations. GitHub’s general security controls do not establish that restriction. The reviewed disclosures also do not establish a Pages-log retention period or a way for Orbit to delete a particular visitor’s hosting logs. We make no such promises.

School staff should obtain clarification of these hosting policies before relying on that exception. This notice documents the reviewed workflow and its limits; it does not establish COPPA compliance.

What the school controls

Browser extensions, device monitoring, Enhanced Spell Check, dictated keyboard input, cloud-synced download folders, backups and operating-system services are outside Orbit's control. Ask IT to review those settings. Use local spell checking and local or USB save destinations when content must stay on device. Do not treat this page as a promise about those separate systems.

Before students arrive

  1. Allow this site, service workers, local browser storage, WebAssembly and the microphone/camera features your lessons use.
  2. On an actual managed student profile, open Orbit while online. The desk opens without a full-toolkit download. Allow extra storage for media; the optional complete offline toolkit is roughly 350 MB.
  3. Make a practice story, use Studio and record a short take. If offline lessons are needed, choose Files → Prepare for offline use and wait for Ready to work offline. Disconnect Wi-Fi and check the lesson.
  4. Finish session, check the exported .chatter files or session ZIP, then reopen a story file. Confirm which folder IT permits.
  5. Check what logout does to local browser storage. If it is erased, the site loads its tools again next session. Always export work before logout.

Patching

An update waits for all Orbit tabs and app windows to close. Save the session first, then reopen the homepage. Updated tools load as needed. Prepare the new release separately if you need its complete toolkit offline. Workspace recovery keeps the same local identity across app releases. Exported files remain the dependable handoff. Never clear site storage as an update step.

Device expectations

Managed Chromebooks with current Chrome are the primary school target. Mac and Windows Chrome use the same site. Recent Safari on iPhone and iPad can use local downloads; iOS/iPadOS 18.4+ is the pilot target. Studio, video encoding and recording still need a real-device check. Full offline preparation covers app tools, not the external source/license archives linked below. Download those separately while online if you need them. A ZIP session is limited to 256 MB before packing; use individual story saves or the verified folder option for larger sessions.
