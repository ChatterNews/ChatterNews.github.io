Your work.
Your device.

Orbit is a static website with a local workspace. It has no student account server, cloud storage, analytics service, or automatic publishing connection.

What stays local

Story text, recordings, images, projects, badges and crew notes are stored in the browser on this device. Transcription and image checks run here too. Saving creates files in a folder you choose or starts a browser download. The website edition does not open a sharing service.

What uses the internet

First preparation downloads the app and its models. The browser also checks for app updates. GitHub receives ordinary connection information, including IP addresses and requested public file paths. Orbit's working app reads its prepared cache; missing resources fail closed instead of using a remote fallback. Story navigation uses URL fragments, which are not sent in HTTP requests.

What the school controls

Browser extensions, device monitoring, Enhanced Spell Check, dictated keyboard input, cloud-synced download folders, backups and operating-system services are outside Orbit's control. Ask IT to review those settings. Use local spell checking and local or USB save destinations when content must stay on device. Do not treat this page as a promise about those separate systems.

Before students arrive

  1. Allow this site, service workers, local browser storage, WebAssembly and the microphone/camera features your lessons use.
  2. On an actual managed student profile, prepare Orbit while online. Allow roughly 350 MB for the app, plus room for recordings and exports.
  3. Open Orbit, make a practice story, use Studio and record a short take. Disconnect Wi-Fi and confirm the lesson still works.
  4. Finish session, check the exported .chatter files or session ZIP, then reopen a story file. Confirm which folder IT permits.
  5. Check what logout does to local browser storage. If it is erased, prepare again next session and always export work before logout.

Patching

An update waits for all Orbit tabs and app windows to close. Save the session first, reopen the homepage, and prepare the new toolkit. Workspace recovery keeps the same local identity across app releases. Exported files remain the dependable handoff. Never clear site storage as an update step.

Device expectations

Managed Chromebooks with current Chrome are the primary school target. Mac and Windows Chrome use the same site. Recent Safari on iPhone and iPad can use local downloads; iOS/iPadOS 18.4+ is the pilot target. Studio, video encoding and recording still need a real-device check. A ZIP session is limited to 256 MB before packing; use individual story saves or the verified folder option for larger sessions.
